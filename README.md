# A Music Box to Help Babies Sleep

胎内音響プロファイリングに基づく、赤ちゃん寝かしつけ用オルゴール PWA。

作り手の主観（恣意性）を排し、音響学・小児科学・発達心理学の文献データから
導き出したパラメータに基づいて、新生児・乳児の入眠と自律神経の安定を促す
Web アプリを、無料・完全オープンソースで開発するプロジェクト。

目的は収益ではなく、赤ちゃんの睡眠研究が前に進むことと、睡眠と発達の
関連を追うこと。広く知ってもらうための発信（売り込み）はその手段として
行う。方法論とデータを公開し、誰が使ってもよい形にすることで、他の
誰かが続きを進められる状態を作る。

## 構成

3つの音響レイヤーを独立にミックスできる設計。

| レイヤー | 内容 |
|---|---|
| オルゴール | パブリックドメイン楽曲を無限ループ化した主旋律（倍音を抑えた音色） |
| 心音 | 母体安静時心拍（BPM 60〜80）を基準に、導入時は速めから減速するエントレインメント |
| さざ波（胎内音） | 羊水の中の音響環境そのもの。母体の血流音を主体とする暗騒音をノイズ生成で自作し、心音の BPM に同期してゆらがせる |

数値パラメータ（BPM・周波数帯域・音圧上限など）は文献レビューの
実測集計から決める。ただしテンポは、文献統計としては存在せず、
生理学側の仮定として扱う（`METHODOLOGY.md` の「統計処理と
パラメータ決定ルール」の節の初回集計。仮定の出典・更新条件は
【要決定：CONF-010】。裁定記録は `CONTRADICTIONS.md` の CA-004 の項参照）。
決定ルールと母集団は [METHODOLOGY.md](METHODOLOGY.md)、
音響・UX の設計仕様は [DESIGN.md](DESIGN.md) を参照。

## 文書の正本と優先順位

文書・記録・データの間で記述が食い違う場合に、どれを正とするかを
この節に定める。上位のものが下位のものに勝つ。

### 正本の階層（推奨）

次の階層は推奨であり、原作者の確認を経るまで確定事項として
扱わない。

| 順位 | 文書群 | 扱い |
|---|---|---|
| 1 | 中核の仕様文書（`README.md`、`DESIGN.md`、`METHODOLOGY.md`） | 正本。不一致があった場合は、この階層の記述が勝つ |
| 2 | 領域別の正本 | 定められた適用範囲の中でのみ正本とする。適用範囲と中核仕様との優先関係を、領域別の正本と中核仕様の両方に記す |
| 3 | 日付付き記録文書 | 証拠・作業記録とする。記録の記述は、それだけでは仕様を変更しない |
| 4 | 実装物・生成物（コード、設定ファイル、生成された音源・出力） | 仕様の証拠としない。実装物の存在は、仕様要件の定義とはみなさない |

### すでに定まっている優先・正本の記述

次の記述は、原文に確認できるものであり、適用範囲は各記述に
記された範囲に限る。一般の紛争解決方針ではない。

- 数値パラメータの最終決定は、`METHODOLOGY.md` の文献レビュー
  結果に従う（`DESIGN.md` の冒頭の説明）。適用範囲は数値の決定のみ。
- 端末スピーカー一次情報の方法論・物理前提・抽出ルールは、
  `literature/device_acoustics/SOURCES.md` を正とする
  （`METHODOLOGY.md` の「母集団」の節）。適用範囲は端末補正の
  根拠のみ。
- 抽出シートは `PMID` ごとに1行とし、バリデータの `PMID`
  重複禁止を正とする（`METHODOLOGY.md` の「抽出ルール」の節）。
  適用範囲は抽出シートの形式のみ。

### 未決定の優先順位

- 中核の仕様文書3件の間で、数値の決定以外の事項について
  不一致があった場合の優先順位は、【要決定：CONF-058】とする。
- `app/presets.json`（正本プリセット）と仕様文書の記述との間で
  不一致があった場合の優先順位は、【要決定：CONF-058】とする。
  なお、`DESIGN.md` の「プリセットの `JSON` 形式」の節は、
  `app/presets.json` を正本プリセットと述べる。これは
  プリセットの置き場所としての正本であり、仕様文書との
  優先順位を定めたものではない。
- 領域別の正本の一覧と、各正本の適用範囲は、【要決定：CONF-058】
  とする。端末情報の方法論メモ以外の領域別正本の有無を含む。
  現時点で確認できる領域別の正本は、上記の
  `literature/device_acoustics/SOURCES.md` のみである。

### 矛盾の扱いと仕様への反映（推奨）

- 新たな矛盾が見つかった場合は、記録し、原作者確認に回し、
  黙って解決しない。
- 記録が仕様の変更を示唆する場合は、仕様への反映を経て初めて
  正本となる。記録側の更新だけで、仕様が変わったものとして
  扱わない。仕様へ反映した場合は、記録側の状態表示を更新する
  ことを義務づける。
- 仕様への反映が済んだ記録は、状態を表示して残すか、統合して
  廃止する。どちらの扱いとするかは、記録ごとに目録に記す。
