# Phase 4（音響評価・公開判断）の前提条件チェックリスト（2026-11-17）

GitHub Issue #13 の受け入れ条件として、先送り・実機未確認の束を
Phase 4 の入口条件に固定する。**このリストの項目が監査文書へ
結果追記されるまで、公開判断をしない。**

## 前提条件

- [ ] **実ブラウザ・実機確認**（スマホ実機）
  - ACID/RASIS 監査の F2/F3/F9/F11（再生中にしか起きない経路）
  - 監査修正第2弾（Issues #1〜#4, #11）の実機経路: プリセットの
    保存/削除/取込、低速回線での曲変更・ローパス変更、二重タップ
  - 結果は analysis/acid_rasis_audit_2026-11-17.md へ追記する
- [ ] **Content-Security-Policy の要否判断**
  - 実機確認ができない段階では入れない（壊す方が悪い）という
    先送り判断の再確認。実機確認とセットで決める
- [ ] **合否基準の事前登録**（Issue #8）
  - 5つの決定（判定距離・上限・端末音量・平均時間 T・不合格時の
    対応）を確定し、pass_criteria を「登録済み」に改める。
    A 層測定は登録後にしか始めない（事後選択の防止）
- [ ] **A 層（実機 SPL）測定の実施条件**
  - 校正済み騒音計が無い段階では相対比較のみ。絶対値の合否判定は
    校正済み機器が前提（IEC 61672、LAeq/LAFmax/LCpeak）
- [ ] **監査台帳の判断**（Issue #7 の実質側）
  - 全24パラメータの decision / evidence_grade は A 層測定の結果と
    合わせて人が判断する。バリデータの警告表示がその進捗を示す

## 完了の記録方法

各項目は、実施日・結果・根拠へのリンクをこのファイルへ追記して
チェックを入れる。公開判断そのものは DESIGN.md の Phase 4 の
記録として別途残す。
