# 監査台帳パラメータ別 根拠ノート（2026-11-17）

analysis/acoustic_evidence_audit.json の24パラメータについて、
台帳の順に、(1) リポジトリ内に既にある根拠、(2) 既存音源から
測れるもの、(3) 未解決・不足しているもの、だけを整理した作業
ノート。等級・分類・判断は付けない（それらは監査で人が記録
する分であり、このノートはその材料集めである）。

デジタル音源の測定値（LUFS-I / dBTP / Crest Factor /
1/3オクターブ / Spectral 系）は analysis/audit_metrics_2026-11-17.csv
（作成中）が正本になるため、ここでは個別の数値は繰り返さない。

## master_limit（マスター上限 0.9）

- リポジトリ内の根拠: app/app.js の冒頭 TODO と定数コメントに
  「最大音量リミッター値が安全側統計から決まるまでの従来値」と
  明記（audio/provisional_values_2026-11-17.md の項目1も同じ
  位置づけ）。監査計画 §5 は「デジタル Gain 0.9 は耳元の音圧や
  安全性を保証しない」と明記。analysis/evidence_references.csv
  には Hugh 2014（一次抄録照合済み）・Erbele 2024（二次裏付け）・
  AAP 2023 が本パラメータに紐付けて登録されているが、いずれも
  実機の耳元 SPL に関する資料であり、デジタル値 0.9 自体の
  根拠ではない。
- 既存音源から測れるもの: ミックスのピーク・True Peak・LUFS は
  デジタル側の上限として測定可能（audit_metrics 参照）。耳元
  SPL は音源ファイルからは測れない。
- 未解決: 実機・距離・端末音量設定を含む耳元 SPL の測定が無い。
  校正済み騒音計が必要で、現状は機材でブロックされている
  （監査計画「外部レビュー反映」Q2 の線引き参照）。同レビューは
  本値を「未解決ではなく制御不能な前提として別枠」とする案を
  出しているが、台帳への反映は未判断。

## preset_soothe_decel（減速 180 秒）

- リポジトリ内の根拠: DESIGN.md §5 のプロファイル定義
  「BPM 85〜90 + 強めのさざ波で開始し、数分で BPM 65 へ減速」
  と §1 のエントレインメント記述が qualitative な出所。
  app/presets.json の当該プリセット説明にも「『数分』は仮に
  180 秒とした仮置き」と明記。audio/provisional_values_2026-11-17.md
  項目2も同じ整理（開始 BPM 88 は 85〜90 の中央という規則由来で
  ある点も併記）。
- 既存音源から測れるもの: 減速を実装したレンダーはリポジトリ
  内に無い（オフライン版 render_mix.py は 70 BPM 固定で、
  docstring に「減速カーブは後段の話で、ここでは適用しない」と
  明記）。したがって実包絡としての測定対象はまだ存在しない。
- 未解決: 「数分」を 180 秒とする根拠はリポジトリ内に無い。
  減速カーブの形（BPM 軌跡）も未定義。

## preset_soothe_waves（さざ波 100）

- リポジトリ内の根拠: DESIGN.md §5 の「強めのさざ波」という
  qualitative な記述が出所。app/presets.json の説明に「さざ波
  最大で開始」とあり、audio/provisional_values_2026-11-17.md
  項目2は「『強め』を最大で解釈」と整理している。
- 既存音源から測れるもの: 現行の設計バランスでの血流レベルは

  スライダ 80 の位置）で参照できる。ただしスライダ 100 の位置が
  実レベルで何 dB 上がるかは、アプリのゲイン構成からの換算に
  なる。
- 未解決: 「強め」を最大値と解釈する根拠はリポジトリ内に無い。
  鎮静用途でのさざ波レベルの実測・文献資料も無い。

  analysis/song_transfer_comparison.csv にある。候補値が決まれば
  同じ方法で帯域別エネルギーを比較できる（監査計画の測定指標 C
  の方針どおり、カットオフだけでなく帯域エネルギーで見る）。
- 未解決: 「深め」の数値定義そのものが無い。250 Hz からどの
  程度・どの形で深めるかの規則も未定義。

## design_reverb_decay（リバーブ Decay 0.8〜1.2 秒）

- リポジトリ内の根拠: DESIGN.md §3 の「リバーブは短いルーム

- 既存音源から測れるもの: 現行音源にルームリバーブは入って

- 未解決: Phase 2 の実装時に値と定義（何の減衰時間か）の

## klank_partial_amps（Klank 振幅比 1 : 0.32 : 0.12 : 0.05）

- リポジトリ内の根拠: audio/render_klank.py の docstring が

  由来であることを明記。audio/render_songs.py の試聴用加算
  モデルも同じ振幅比（PARTIALS の 1.0 / 0.32 / 0.12 / 0.05）を

- 既存音源から測れるもの: Klank レンダー（素の4曲）の単音
  減衰部から倍音ごとの振幅を推定できる。方法と結果は

- 未解決: 実測・文献による検証は無い、と

## surge_shape（surge 包絡 0.55 + 0.45·exp(−4·phase)）

- リポジトリ内の根拠: audio/render_mix.py の womb_flow が式の
  正本で、血流が心拍同期であることの生理的な動機は DESIGN.md
  §2 にある。audio/provisional_values_2026-11-17.md 項目8は
  「生理学的な動機はあるが実測値ではない設計判断（文書化
  済み）」と明記。25 ms 平滑化については audio/render_bed_sox.py
  が、平滑化なしでは拍の折り返しごとに 0.442 のゲイン段差が
  出ることを測定し、平滑化で段差が消えることと粗さの改善
  （1.61 → 1.55 dB）を実測で記録している。app/app.js の
  surgeCurve も同じ形と平滑化を実装し、平滑化後のピークは
  オフライン連続計算の実測（0.89）と一致する形になっている。
- 既存音源から測れるもの: bed_only.wav / bed_sox.wav から包絡を
  取り、Modulation Depth / Rate を測れる（audit_metrics 側）。
  拍同期であることは心音ステムとの位相比較でも確認できる。
- 未解決: 0.55 / 0.45 / 4.0 という数値自体の実測出典は
  リポジトリ内に無い。

## heart_decay（心音の減衰率 22/s）

- リポジトリ内の根拠: audio/render_mix.py の heartbeat が
  exp(−22t) の包絡と burst 長 0.16 秒を実装し、app/app.js も
  HEART_DECAY = 22 として同じ形（setTargetAtTime の時定数
  1/22 で実現）。対照として、同じ心音モデルの 55 Hz と
  lub-dub 間隔 280 ms には render_mix.py の Parameter bases に
  典拠と確定判断の記録があるが、22/s には無い。
  audio/provisional_values_2026-11-17.md 項目9は「モデル値」と
  明記。
- 既存音源から測れるもの: bed 系 WAV の心音 burst の包絡から、
  実装どおりの減衰になっているかは確認できる（実装の検証で
  あって、値の根拠にはならない）。
- 未解決: 実測の心音スペクトル・包絡に基づく出典はリポジトリ
  内に無い。なお心音の周波数については「実測に基づかなくて
  よい」というユーザーの判断が audio/noise_target_2026-11-16.md
  の決定節にあるが、減衰率への言及はない。

## music_norm_rms（音楽の正規化目標 RMS 0.10）

- リポジトリ内の根拠: app/app.js の MUSIC_NORM_RMS と
  loadSong の実装が定義の正本（統合曲線でフィルタした後の
  バッファ全長の RMS を 0.10 に揃える、単一チャンネル）。
  audio/provisional_values_2026-11-17.md 項目11は「層間
  バランス比は実測導出だが、絶対水準は任意に置いた値」と
  明記。バランス比側の実測は analysis/four_songs_measurements.csv
  （発音中バランス等）と app/app.js 冒頭の導出メモにある。
  監査計画 §5 は「RMS はラウドネスや安全性の指標そのものでは
  ない」と注意し、analysis/evidence_references.csv でも本
  パラメータは Hugh 2014 等の SPL 文献と紐付いているが、
  それらは再生時の耳元レベルの話で、このデジタル正規化値の
  根拠ではない。音圧中央値 60 dB（literature/extraction_
  batches/design_stats_summary.md）も再生時キャリブレーション
  の話として audio/noise_target_2026-11-16.md が切り分けている。
- 既存音源から測れるもの: 正規化後の RMS・LUFS-I・ピークは
  デジタル指標として測定可能（audit_metrics 側）。オフライン
  版は正規化ではなく GAIN_MUSIC のゲイン補償方式であり、
  方式が違う点に注意。
- 未解決: 0.10 という絶対水準の根拠なし（バランス比と分けて
  扱う必要がある）。実機での再生レベルとの対応も未測定。
