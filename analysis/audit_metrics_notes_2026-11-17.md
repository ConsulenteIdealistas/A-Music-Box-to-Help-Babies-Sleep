# 監査メトリクス測定ノート（2026-11-17）

対象: SoX ベッド版ミックス4曲、Python 版ミックス4曲、ベッド2種の
計10ファイル。測定は analysis/measure_audit_metrics.py、
結果は analysis/audit_metrics_2026-11-17.csv。
A 層（実機 SPL）は校正済み騒音計が無いため対象外。

## 定義（固定した約束）

- B 層は ffmpeg の ebur128（BS.1770 / EBU R128）。LUFS-I、LRA、
  dBTP はサマリーブロックの値。
- LUFS-M 最大値と LUFS-S 最大値は、ebur128 のフレームログ
  （約100 ms 間隔で M: と S: が記録される）から全区間の最大を
  取った。M は 400 ms 窓、S は 3 秒窓、いずれも ffmpeg の計算値。
  フェードイン／アウト区間も含む。
- C 層は 4096 点 Hann 窓、50% オーバーラップのパワースペクトルを
  全区間で平均し、DC ビンを除いて集計した。重心・帯域幅・
  フラットネス・ロールオフはこの平均パワースペクトルから計算。
- 1/3 オクターブ帯域は公称中心 25 Hz〜16 kHz、端は中心×2^(±1/6)。
  帯域レベルは全パワーに対する比（dB）で、窓長やファイルの
  絶対レベルに依存しない形にした。
- ロールオフは累積パワーが全体の 85% に達する周波数（85% は
  librosa 既定の約束として固定）。
- Crest Factor は全区間の peak/RMS（dB）。

## 検証結果

- Python 版4曲の RMS は four_songs_measurements.csv の
  rms_mix_py と5桁すべて一致（0.09217 / 0.08124 / 0.12623 /
  0.07568）。
- SoX 版4曲＋bed_sox の LUFS-I / dBTP は、先行測定値と完全一致
  （−20.5/−5.4、−21.5/−5.3、−16.9/−1.0、−21.5/−4.8、
  −41.1/−19.7）。
- 重心は旧測定（8192 点窓）と全曲 1 Hz 以内で一致。窓長を
  4096 に変えても重心は実質動かない。
- **ピークの不一致（要記録）**: 旧 CSV の peak_mix_sox は、
  歌に生き（0.79068）とゆりかご（0.56091）が今回の
  サンプルピーク（0.88995 / 0.57440）と合わない。原因は旧
  スクリプトが SoX stat の "Maximum amplitude"（最も大きい
  正のサンプル）を読んでいたこと。この2曲は負側の振幅の方が
  大きく、SoX の "Minimum amplitude" は −0.889954 /
  −0.574402 で今回の max| x | と一致する。旧列は「正側の
  最大」であってピークではない。ブラームスとモルダウは正側が
  最大だったため一致していた。

## 観察と異常

- SoX 版と Python 版のミックスは、LUFS-I と dBTP が全曲
  0.1 dB の分解能で一致。RMS の差は最大 0.00007（フェード分の
  差）。ただしブラームスの LRA は 16.4（SoX）と 15.4
  （Python）で 1 LU 違い、LRA はフェード形状の差に敏感。
- **25 Hz 帯域は全ファイル −200 dB（床値）**。4096 点 FFT
  （44.1 kHz）のビン間隔は約 10.8 Hz で、25 Hz 帯域
  （22.3〜28.1 Hz）に入るビンが存在しないため。この窓長と
  サンプルレートの組み合わせでは 25 Hz 帯域は分解できない。
- ベッド2種はほぼ定常: LRA 1.1〜1.2 LU、LUFS-S 最大値と
  LUFS-I の差は 0.7〜0.8 LU。重心は約 130 Hz、ロールオフ
  85% は 64.6 Hz で、エネルギーは 55 Hz の心音と低域の
  血流に集中している。
- bed_sox は bed_only より RMS が小さい（0.01340 vs
  0.01378）。フェード分の差で、先行検証と整合。
- フラットネスはミックスで 0.0001〜0.0003、ベッドで 0.0071
  と小さい。これは全帯域（〜22 kHz）で計算しているためで、
  ローパスで空になった高域ビンが幾何平均を引き下げている。
  帯域内の平坦さではなく全帯域の指標として読むこと。
- 歌に生きが最も大きい（LUFS-I −16.9、dBTP −1.0）。ミックス
  時にピーク 0.89 の書き出し規則が効いたファイルであることと
  整合する。

## 注意（解釈の限界）

- LUFS は耳元の音圧ではない。安全性の判断は A 層（実機 SPL）
  で行い、B 層は再現性の管理に使う。
- K 特性は低域を割り引く。ベッドは RMS −37.2 dBFS に対して
  LUFS-I −41.0 で、55 Hz 中心の実エネルギーより小さく出る。
  心音・血流の評価を LUFS だけで行わないこと。
- LUFS-S は3秒窓のため、断続的な音（フレーズ間隔のある
  オルゴール）では値が揺れる。最大値は「最も大きい3秒」の
  記録として読む。
- 帯域レベルは相対値（全パワー比）。帯域ごとの絶対レベルが
  必要な場合は RMS と組み合わせて読む。

## 膝感度（2026-11-17 追記）

統合曲線の膝（1極ローパス、render_mix.py の lowpass と同一
実装）を 200 / 250 / 315 Hz に動かしたときの感度を、Klank
素音源4曲と bed_only.wav で測った。測定定義は本書の B/C 層と
同一（analysis/measure_knee_sensitivity.py、結果は
analysis/knee_sensitivity_2026-11-17.csv）。

Klank 4曲の平均（250 Hz 基準）:

- 250→200 Hz: LUFS-I −1.45 LU、重心 −23 Hz、1000 Hz 帯域
  −0.40 dB、2000 Hz 帯域 −0.47 dB、500 Hz 帯域 −0.18 dB。
  250 Hz 帯域の相対シェアは +0.33 dB 上がる
- 250→315 Hz: LUFS-I +1.48 LU、重心 +24 Hz、1000 Hz 帯域
  +0.44 dB、2000 Hz 帯域 +0.56 dB、500 Hz 帯域 +0.13 dB

読み方: 帯域レベルは全パワー比の相対値なので動きは小さいが、
LUFS-I は ±1.5 LU 程度動く。膝の選択は主に「全体の明るさ・
音量感」に効き、帯域バランスの形は緩やかに変わる。
bed_only.wav はエネルギーが 55 Hz 中心で膝より十分低いため
LUFS-I は ±0.1 LU しか動かない（帯域シェアは 500〜2000 Hz で
±1.4〜1.9 dB 動くが、絶対シェア自体が −34 dB 以下と小さい）。
なお bed_only は整形済みのベッドへの追加1パスの測定であり、
設計操作そのものの感度ではない。音楽層の膝の感度は Klank
4曲の数値を正とする。

## 再レンダーによる更新（2026-11-17 追記）

本 CSV の測定後に、render_mix.py へ surge 包絡の 25 ms 平滑化を
入れ（SoX 版・アプリと同方式）、Python 版ミックスとベッドを
再レンダーした。新しい Python 版ミックスの LUFS-I は本 CSV の
SoX 版の値と 0.1 LU の分解能で一致する（−20.5 / −21.5 /
−16.9 / −21.5、ベッド −41.0）。本 CSV は測定時点の記録として
そのまま残す。現行ミックスの測定は four_songs_measurements.csv
（再実行済み）を参照。
